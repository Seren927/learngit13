# 评分规则

OpenRepoLens 使用 100 分制。总分达到 95、90、80、70、60 分时分别对应 A+、A、B、C、D，其余为 E。单项得分达到上限记为通过，达到 60% 记为建议，低于 60% 记为缺失。

## 许可证（15 分）

| 检查 | 分值 | 判断方式 |
| --- | ---: | --- |
| 许可证文件 | 10 | 根目录存在 LICENSE、LICENSE.md、LICENSE.txt 或 COPYING |
| 许可证可识别 | 5 | 正文符合 MIT、Apache-2.0、GPL-3.0、BSD-3-Clause 或 MPL-2.0 的常见特征 |

## README（25 分）

| 检查 | 分值 | 判断方式 |
| --- | ---: | --- |
| README 存在 | 5 | 根目录存在 README 文件 |
| 内容完整度 | 5 | 文本长度不少于 800 个字符 |
| 安装与使用 | 4 | 包含安装、快速开始、Usage 等章节 |
| 功能说明 | 3 | 包含功能、特性或 Features 章节 |
| 可视化材料 | 3 | 包含 Markdown 图片、HTML 图片或 shields.io 徽章 |
| 社区入口 | 3 | 链接贡献、许可证或行为准则 |
| 反馈渠道 | 2 | 提供 Issue、Discussions 或维护者入口 |

## 项目文档（20 分）

| 检查 | 分值 | 判断方式 |
| --- | ---: | --- |
| 贡献指南 | 5 | 存在 CONTRIBUTING 文件 |
| 行为准则 | 4 | 存在 CODE_OF_CONDUCT 文件 |
| 安全策略 | 4 | 存在 SECURITY 文件 |
| 文档目录 | 4 | docs/ 至少有两篇 Markdown 文档 |
| 版本记录 | 3 | 存在 CHANGELOG 文件 |

## 开放协作（20 分）

| 检查 | 分值 | 判断方式 |
| --- | ---: | --- |
| Issue 模板 | 6 | `.github/ISSUE_TEMPLATE/` 中存在模板 |
| Pull Request 模板 | 5 | 存在 PR 模板 |
| 公开路线图 | 3 | 根目录存在 ROADMAP |
| 社区说明 | 3 | 存在社区协作文档 |
| 维护者信息 | 3 | README 中出现维护者、贡献者或贡献指南信息 |

## 工程质量（20 分）

| 检查 | 分值 | 判断方式 |
| --- | ---: | --- |
| 自动化测试 | 5 | tests/ 中存在测试文件 |
| 持续集成 | 5 | `.github/workflows/` 中存在 YAML 工作流 |
| 项目元数据 | 3 | 存在 pyproject.toml |
| 忽略规则 | 3 | 存在 .gitignore |
| 代码质量配置 | 2 | 存在 Ruff、Pyright、Mypy 或 ESLint 配置 |
| 可执行入口 | 2 | 存在 `openrepolens/__main__.py` 或 `src/__main__.py` |

## 解释边界

文件存在不等于内容质量高，公开指标也不能完全代表社区活力。该工具适合发现基础治理缺口，不建议将总分作为评价个人或项目价值的唯一依据。读者应优先关注缺失项和证据，而不是只比较分数高低；同时应结合项目阶段、目标用户与实际维护成本共同解读。
